语言润色类 Skill 看起来是轻量工具，实际很容易暴露内部 AI 应用中的反幻觉问题。
这类 Skill 通常不直接做业务判断，也不直接生成正式结论。常见流程只是用户输入一段草稿，Skill 检索相似材料或历史模板，再输出一版更符合内部表达习惯的文本。为了让输出更贴近内部表达，往往会接入历史报告、问题表、项目材料、模板库或术语表。模型检索到相似材料后，生成结果会更接近部门过往写法。
实际使用中，风险往往出现在接入部门知识库之后。模型检索到相似历史材料，输出会明显更接近内部文本。但与此同时，它也更容易把历史材料中的金额、主体、制度、风险等级、整改状态带入当前文本。这样的结果格式更完整，语气更正式，但事实边界已经发生变化。
因此，以语言润色类 Skill 为切口，它能说明部门内部 Skill 在接入知识库后，需要提前建立反幻觉机制。重点在于：模型检索到内部材料后，怎样识别材料的使用权限。
一、内部知识库为什么有必要
部门内部做 Skill，单靠通用模型很难稳定。
通用模型有较强的语言处理能力，可以改写文字、整理结构、统一语气。但很多内部文本任务并不只是在处理语言。同一类问题过去怎么表述，标题写到什么颗粒度，风险影响写到什么强度，哪些字段必须保留，哪些表达不宜扩展，这些信息往往来自部门长期积累。
这类经验通常分散在历史报告、问题表、项目复盘、模板文件、术语表和成员经验中。把这些材料整理成可检索、可标注、可调用的知识库，Skill 才能获得稳定的内部上下文。
对语言润色类 Skill 来说，内部材料的价值可以分为三类：
类型
典型材料
对 Skill 的作用
表达类材料
历史报告、历史问题表、术语表
参考同类问题的表述方式、标题颗粒度、风险表达强度
结构类材料
标准模板、字段说明、分类表
对齐固定结构、输出格式、字段顺序和问题类型
经验类材料
项目复盘、历史整改建议、成员经验
提供常见场景、处理思路和建议类输出的候选参考
没有内部知识库，模型只能依赖用户临时输入和通用表达。生成结果可能语言流畅，但容易偏泛；结构可能完整，但不一定符合部门历史口径；同类问题在不同轮次中也可能出现表达漂移。
一个基本链路可以概括为：
历史材料 / 模板 / 项目经验
        ↓
部门内部数据库
        ↓
可检索、可标注的知识库
        ↓
Skill 根据任务调用相关材料
        ↓
生成更贴近内部口径的结果
        ↓
人工反馈与修正
        ↓
反哺知识库
这条链路能够提升 Skill 的场景适配能力，同时也引入了新的反幻觉要求。
二、知识库接入后的幻觉风险
知识库可以减少模型自由发挥，但检索结果本身也可能成为幻觉来源。
语言润色类 Skill 的典型风险在于：模型检索到一条相似历史材料后，把其中的事实、主体、金额、制度或结论迁移到当前文本。错误内容有来源，但这个来源并不属于当前任务。
例如，用户当前输入只有：
部分流程审批记录不完整。
知识库召回的历史案例中，可能包含合同审批、供应商准入、付款节点、预算控制等内容。它们在语义上接近，都与流程审批有关。但当前输入并未提到合同、供应商、付款节点和预算控制。
如果模型直接套用历史材料，输出可能变成：
相关业务流程审批记录留存不完整，反映出合同管理及付款控制环节存在薄弱点。
这段文字格式更完整，也更接近正式材料。但其中的合同管理、付款控制、管理薄弱点，没有来自当前输入。模型把历史案例中的内容带入了当前文本，生成结果已经偏离原始事实。
语言润色类 Skill 中常见的知识库型幻觉，可以归为四类：
类型
具体表现
事实迁移
从历史材料中补入金额、时间、部门、系统、项目、人员等当前输入没有的信息
判断迁移
将历史案例中的风险等级、问题原因、整改状态、严重程度带入当前文本
来源错配
把历史报告、历史问题表、知识库召回内容写成当前依据
模板越界
因模板字段完整，自动补齐当前输入没有提供的内容，如建议、责任方、时限
这类风险说明，内部知识库并不天然提升生成可信度。知识库提供历史上下文，当前输入决定事实边界。两者之间需要明确的调用规则。
三、反幻觉机制的基本框架
语言润色类 Skill 的反幻觉，可以按照四层来构建：
输入层：确认用户当前输入能支撑什么
检索层：判断召回材料属于什么用途
生成层：限制模型能写什么、不能写什么
输出层：暴露来源、修改点和待确认项
这四层对应的控制目标如下：
层级
控制目标
具体做法
输入层
明确当前事实边界
识别输入类型、事实字段、缺失信息
检索层
明确历史材料用途
区分表达参考、候选参考、禁止迁移内容
生成层
限制擅自扩写
设置字段级硬约束和禁用表达
输出层
支持人工复核
输出参考来源、未迁移信息、待确认事项
这个框架的关键，是把当前输入和历史材料分开处理。当前输入决定正文能写什么，历史材料用于帮助表达贴近内部习惯。
四、检索结果需要分级使用
检索到的历史材料不能整体进入生成结果。不同类型的信息需要不同权限。
使用等级
包含内容
处理方式
可直接使用
句式结构、标题颗粒度、常用术语、输出格式
用于组织语言、统一表达和对齐模板
谨慎使用
问题分类、风险表述强度、整改建议、同类问题描述
只能作为候选参考，需要当前输入支撑
禁止迁移
历史金额、主体、制度、风险等级、整改状态、具体原因
不得写入当前正文，不得作为当前依据
这类分级能解决一个关键问题：模型可以看到历史材料，但不能把看到的内容全部写入当前文本。检索命中只说明材料可能相关，不说明材料中的事实适用于当前任务。
五、高风险字段要单独约束
只在规则中写不得编造事实，约束力度通常不够。语言润色过程中，模型容易进行自动补充、概括和扩写。更有效的做法，是把高风险字段拆开处理。
字段类别
典型字段
约束规则
事实字段
金额、笔数、比例、时间、抽样规模
用户提供则原样保留；用户未提供则不得补充
主体字段
部门、系统、供应商、人员、项目名称
用户提供则保留；未提供时使用通用描述，不从历史材料补具体名称
依据字段
制度、合同、流程规范、审批规则
用户提供具体依据时才能引用；历史材料中的依据不得套用
判断字段
风险等级、问题原因、定性强度、整改状态
需要当前输入支撑；不得因历史案例相似而升级或弱化
建议字段
整改建议、责任方、完成时限、整改动作
用户要求建议时才输出；具体责任和时限需要当前事实支撑
可以通过一些具体规则降低风险：
* 用户写“涉及 3 笔、12 万元”，输出不能改成“涉及 XX 笔、约 XX 万元”。
* 用户只写“权限配置存在问题”，输出不能补成“涉及 56 笔，金额 12.3 万元”。
* 用户没有提供制度依据时，不生成制度对照段。
* 历史案例中的制度名、部门名、项目名不进入当前正文。
* “未及时关闭”不改成“严重滞后”，“部分不符”不改成“大量不符”，“未审批”不弱化为“审批流程待完善”。
* 用户只要求润色问题描述时，不自动生成整改建议、责任方和完成时限。

这些字段是幻觉的高发位置。反幻觉机制如果能管住这些字段，输出风险会明显下降。
六、知识库建设要标注调用边界
面向 Skill 调用的知识库，不能只集中存放原文。材料进入知识库时，最好同步标注使用边界。
可以按照四类字段整理：
字段类别
可包含字段
作用
场景字段
场景类型、问题类型、适用限制、更新时间
判断材料是否适用于当前任务
表达字段
表达口径、标题写法、输出格式、术语口径
供模型学习写法和结构
事实字段
事实描述、金额、主体、制度、风险等级、整改状态
作为历史事实保存，默认不迁移到当前正文
控制字段
敏感字段标识、可输出范围、需确认字段
限制模型调用范围，提示人工复核重点
技术上可以完成检索、切片、召回和排序；业务侧需要定义材料的使用权限。哪些内容属于表达参考，哪些内容属于历史事实；哪些可以复用，哪些必须隔离；哪些判断可辅助生成，哪些判断必须人工确认，这些边界需要在知识库建设阶段提前明确。
如果边界不在知识库层面处理，后续只能依赖提示词兜底，稳定性会受到影响。
七、输出结构要支持复核
语言润色类 Skill 如果只给一段最终文本，用户很难判断模型参考了什么、改了什么、是否引入新事实。输出结构可以拆成几部分：
1. 规范化正文
2. 参考口径来源
3. 本次修改说明
4. 未迁移信息说明
5. 待人工确认事项
各部分可以对应不同用途：
输出模块
作用
规范化正文
只写当前输入能够支撑的内容
参考口径来源
展示参考了哪些历史材料或模板
本次修改说明
说明主要改动集中在结构、措辞、标题还是格式
未迁移信息说明
说明知识库中出现但未写入正文的信息
待人工确认事项
标出制度依据、金额、主体、风险等级等需确认内容
其中，未迁移信息说明很重要。比如知识库召回的历史材料中包含金额、部门、制度或整改状态，但当前输入没有对应事实，Skill 可以明确提示这些内容仅作为历史参考，未进入正文。
这样可以让用户看到模型的调用边界，也便于后续复核。
八、反幻觉测试样例要前置
部门内部 Skill 上线前，可以准备一组专门测试反幻觉的样例。测试重点不在于输出是否好看，而在于模型是否守住事实边界。
测试样例可以分为四类：
测试类别
输入设计
观察点
缺失字段测试
不提供金额、主体、制度、时间等信息
是否从历史材料中补充缺失字段
强度控制测试
输入使用“部分”“可能”“疑似”等弱表达
是否升级为确定问题或严重结论
场景干扰测试
召回相似但业务场景不同的历史材料
是否套用历史业务背景、问题原因和责任主体
模板越界测试
模板包含多个字段，但输入信息不足
是否自动补齐整改建议、责任方、时限等内容
如果这些样例能够通过，说明 Skill 的反幻觉约束具有一定稳定性。反之，说明模型仍在依赖历史材料补当前事实，需要继续调整检索、提示词或输出结构。
九、结语
以语言润色类 Skill 为切口，可以看到部门内部 Skill 反幻觉中的一个基础问题：内部知识库接入后，模型获得了更多上下文，也获得了更多错用上下文的机会。
可信输出不能简单理解为：
可信输出 = 检索结果 + 模型生成
更合理的拆解是：
可信输出 = 检索结果分级使用
        + 当前事实隔离
        + 生成边界约束
        + 人工确认点暴露
        + 反幻觉样例测试
检索出来的历史材料不能整体进入生成结果。有些内容可以学习写法，有些内容只能作为候选参考，有些内容必须留在历史来源中。
部门内部 Skill 要真正进入工作流，需要同时解决两个问题：接入内部知识库，让模型获得部门上下文；建立反幻觉机制，让模型识别历史材料的使用边界。语言润色类 Skill 场景较轻，但它暴露的问题具有代表性。把这个场景中的边界处理清楚，后续扩展到总结、报告生成、问题归类、建议生成等任务时，风险会更可控。
